# Omarchy Friends — first 50 users playbook

The product does not need another pile of features before it has liquidity. The first growth problem is making Omarchy feel populated when a new user opens Friends.

## Positioning

Do not pitch this as “leave Discord/Reddit.”

Use:

> **The live human layer for Omarchy — find builders, get help, pair up, share setups and build together without leaving your desktop.**

The differentiated job is not “answer a Linux question better than AI.” It is connecting a real Omarchy machine to real builders, creators, testers and collaborators.

## Seed cohort

Recruit 30–50 real people who are likely to overlap online:

- Omarchy plugin authors;
- theme / rice creators;
- active subreddit contributors;
- active Discord helpers / Rangers;
- contributors who regularly review or test plugins;
- people posting Omarchy builds on X;
- a few newcomers so experienced users have someone useful to help.

Do not fake accounts, fake presence, fake replies or fake activity.

## First-session success

A new install should reach at least one of these quickly:

- see another live Omarchy user;
- wave / chat with someone;
- find a builder with common ground;
- ask for help and get a human offer;
- find a setup/component worth saving;
- join a Build Room;
- offer to test something;
- join a focus/pair session.

An empty room is the existential failure mode. If few people are online, show truthful scheduled community hours, current builds, saved public solution cards and invite actions rather than pretending users are online.

## Acquisition channels

Use Reddit, Discord and X as acquisition channels instead of enemies.

Examples of useful posts:

- “I built an experiment where Omarchy desktops can see other builders online right now.”
- “Need an AMD tester for this plugin — join the Build Room from Omarchy Friends.”
- share a Setup Card / Ship card with a deep link;
- share a solved community issue with the resulting Solution Card;
- announce Ship-It Friday / focus sessions / build challenges.

## Core loop

```text
Discover someone / something
        ↓
Idea / Help / Setup / Build
        ↓
Chat / Pair / Join team
        ↓
Build / Test / Solve
        ↓
Ship / Solution / Setup Component
        ↓
Share externally
        ↓
New Omarchy user installs Friends
```

## Metrics

Do not optimize for GitHub stars first.

Track only privacy-respecting product outcomes. Prefer local aggregation or explicit opt-in telemetry if analytics is ever added.

Useful measures:

- weekly active installs;
- users who saw at least one real other builder;
- first interaction sent;
- first reply received;
- help requests that got an offer;
- Build Rooms that got a second member;
- test requests that got a result;
- Solution Cards verified by another machine;
- users returning the next week.

North-star candidate:

> **Meaningful human connections per week**

## Priority order

1. **Liquidity** — enough real people online at overlapping times.
2. **Trust** — privacy, security boundaries, clear public/private behavior, moderation.
3. **Habit** — help, pair, build, focus, ship, return.

## What not to do

- Do not build a generic infinite social feed.
- Do not add followers/vanity popularity rankings.
- Do not auto-install remote setup data.
- Do not silently upload diagnostics.
- Do not turn every feature into a separate chat system; reuse Friends DMs/groups.
- Do not market private-message security more strongly than has been tested.
- Do not keep adding features before real-user tests reveal a concrete missing workflow.
